01 / GPT IMAGE MODEL

GPT 生图模型：不是“自动画图软件”，而是能够理解上下文的视觉协作者。

模型会把文字、图片和对话中的要求转换为视觉结果。它能做生成，也能做编辑和多轮修改；但模型输出是概率结果，不天然等于正确设计。

先理解模型的工作逻辑

Input → Understanding → Generation → Review
输入信息文字需求、截图、草图、参考图、品牌资料和修改反馈。
语义理解识别任务、对象、场景、视觉风格、布局和限制条件。
视觉生成组合构图、颜色、材质、光影、文字区域和界面元素。
对话修改根据反馈保留有效部分，并修改局部或整体方向。
人工判断检查目标、逻辑、可读性、一致性、真实性和可落地性。

  • 理解“保留结构、降低装饰、突出主按钮”等修改要求。

更适合交给 GPT 的任务

  • 把模糊想法快速变成第一版可视化方向。
  • 在短时间内生成多种风格、构图和素材变体。
  • 对局部区域进行替换、扩展、补充和风格统一。
  • 帮助团队讨论“方向是否值得继续”。

必须由设计师负责的任务

  • 判断产品目标、用户需求和业务优先级。
  • 建立真实的信息架构、交互路径和组件状态。
  • 校正文案、数据、品牌规范和实现逻辑。
  • 把概念图重建为可编辑、可复用、可开发的设计稿。

不要把“看起来像 UI”当成“真正的 UI”

生成图可能拥有漂亮的卡片和按钮，但文字可能错误、状态可能缺失、控件可能无法交互。需要注意：视觉相似不代表结构真实。

快速提问

一张生成的 App 首页很漂亮，但按钮含义不清、数据无法解释，它属于视觉概念、UI 参考还是最终设计稿？为什么？

如何判断“设计相关”？

重点不在画面是否漂亮，而在它是否具有明确目标、载体、规则和后续加工流程。

有目标传播、转化、识别、操作、展示或空间体验。
有载体页面、包装、海报、产品、空间、物料或印刷品。
有约束尺寸、品牌、内容、工艺、交互、成本或施工条件。
有后续需要进入 Figma、建模、排版、打样、开发或施工。
可评估能用功能、识别、可读、统一和落地标准判断。
可迭代能够根据反馈修改结构、信息、风格和细节。

高亮标签 ≠ 一键完成专业设计

GPT 更适合生成方向、概念和视觉参考。以下任务必须继续专业加工：

  • LOGO / VI：检查独特性、注册风险、网格、黑白稿和应用规范。
  • UI / App：重建真实组件、状态、交互、适配和无障碍规则。
  • 包装 / 印刷：补充刀版、出血、文字信息、材质和印刷工艺。
  • 空间 / 施工：核对真实尺寸、结构、安全规范、材料与预算。
  • 数据图表：使用真实数据，保证编码方式、单位和结论准确。

03 / GENERATION METHODS

四种常用生成方式：输入依据不同，控制程度、适用阶段和风险也不同。

选择生成方式时，先判断你手上已经有什么：只有想法、已有画面、明确参考，还是已经画好的布局草图。

TEXT TO IMAGE

文生图

只用文字描述生成新画面，最适合从零探索方向。

输入需求、内容、风格、构图和约束。
适用灵感发散、首轮概念、多风格比较。
优点自由度高、起步快、适合大量变体。
风险结构漂移、文字错误、结果不稳定。
从零开始方向探索
IMAGE TO IMAGE

图生图

上传已有画面，在保留部分内容的基础上修改或重绘。

输入截图、照片、已有设计稿或生成图。
适用换风格、扩图、局部替换、视觉升级。
优点比纯文字更容易保持主体和构图。
风险原图错误可能被继续放大或扭曲。
已有画面定向修改
REFERENCE GUIDED

参考图生成

使用一张或多张参考图控制布局、风格、材质或氛围。

输入布局参考、风格参考、品牌或材质参考。
适用对齐审美、控制气质、统一系列资产。
优点目标更直观，团队沟通成本更低。
风险过度接近参考，产生抄袭和版权问题。
风格控制布局控制
SKETCH TO IMAGE

草图生图

把线框、手绘或低保真结构转换为更完整的视觉方案。

输入线框图、手绘草图、灰度原型或构图框架。
适用固定模块位置、验证布局、从原型到视觉。
优点最容易保留设计师预先确定的结构。
风险结构过于粗糙时，模型会自行补充错误内容。
结构优先原型升级

04 / UI GENERATION WORKFLOW

从需求到第一版 UI 概念图：生成不是一次完成，而是逐步缩小问题范围。

高效工作流的核心是：先定义目标，再拆结构；先定大方向，再调整局部；最后把可用规律转成真实设计。

GPT UI 图像生成 8 步流程

Brief → Figma
01 明确任务产品、页面、用户、设备和核心目标。
02 拆解结构页面区域、模块顺序、核心内容和状态。
03 建立基准确定比例、风格、品牌气质和禁止项。
04 首轮生成一次生成多个方向，不急着修细节。
05 比较筛选用统一标准评估目标、结构和可读性。
06 定向修改每轮只调整一个主要变量。
07 提取规律记录可用布局、配色、组件和视觉语言。
08 设计重建进入 Figma 建立真实内容、组件和状态。
BEFORE

生成前：把需求说清

  1. 明确页面最重要的用户任务。
  2. 列出必须出现的内容和模块。
  3. 确定画布比例、设备和输出用途。
  4. 准备风格关键词与必要参考。
DURING

生成中：控制变量

  1. 首轮比较整体方向，不纠结小字。
  2. 固定结构，只改配色或材质。
  3. 固定风格，只改信息密度或模块。
  4. 明确哪些区域必须保持不变。
AFTER

生成后：转成设计任务

  1. 提取可用的布局规律与视觉语言。
  2. 校正文案、数据、图标和交互逻辑。
  3. 建立网格、组件、状态和响应式规则。
  4. 记录 Prompt、版本和取舍依据。

同一页面的三轮修改示例

第 1 轮：定方向只看是否符合“轻盈、可信、健康”的产品气质。
第 2 轮：定结构要求保留顶部问候、中部健康数据、底部任务区。
第 3 轮：定密度减少装饰，放大关键数据，强化主操作按钮。
关键结论每轮只解决一类问题，结果更容易比较和复盘。
低效：不断重写整段 Prompt每次同时改变布局、内容、风格和配色，无法判断哪个变量有效。
VS
高效：固定主体，逐项微调保留已经成立的部分，每轮只修改一个主要问题，并记录变化。

最常见的工作流错误

一开始就要求“完整、精致、可交付”，会让模型同时处理太多目标。正确做法是先粗后细、先大后小、先方向后规则。

流程口诀

先目标，后结构；先多版，后选择；先大改，后小修；最后回到真实设计工具。

05 / PROMPT STRUCTURE

UI 图像 Prompt：把“想要好看”改写成模型可以执行的设计说明。

一个可用的 Prompt 至少要回答：做什么、给谁用、包含什么、长什么样、输出多大、哪些问题不能出现。

推荐的 8 段式 Prompt 公式

可以写成连续自然语言，也可以分段列出。顺序不是绝对固定，但信息需要完整。

任务＋ 用户＋ 目标＋ 结构＋ 内容＋ 风格＋ 输出＋ 约束
01–02

任务与用户

  • 产品类型：电商、教育、金融、健康、工具等。
  • 页面类型：首页、详情页、Dashboard、登录页等。
  • 目标用户：年龄、职业、经验和使用环境。
03–04

目标与结构

  • 用户进入页面后最重要的任务是什么。
  • 从上到下有哪些区域、模块和操作。
  • 哪些信息必须第一眼看到，哪些属于辅助内容。
05–06

内容与风格

  • 使用真实、简短、可读的文案和数据示例。
  • 指定配色、材质、圆角、阴影、排版和品牌气质。
  • 说明参考的是布局、氛围还是视觉语言。
07–08

输出与约束

  • 手机 9:16、网页 16:9、1440px 桌面画布等。
  • 要求清晰层级、合理留白和真实组件。
  • 避免乱码、过度渐变、装饰堆叠和不可理解图标。

可复制的 Prompt 模板

任务为【产品类型】设计一张【页面类型】UI 概念图。
用户与目标目标用户是【用户】，主要任务是【任务】。
页面结构从上到下包含【区域 1】【区域 2】【区域 3】。
内容使用【语言】真实示例文案，并展示【数据 / 状态 / 图片】。
视觉方向整体呈现【气质】，使用【配色】【材质】【排版】。
输出约束画布为【比例 / 尺寸】，避免【问题 1】【问题 2】。

标注示例：健康管理 App 首页

为年轻职场人设计一张健康管理 App 首页 UI 概念图，手机端 9:16。页面目标是让用户快速查看今日健康状态并开始运动任务。顶部包含问候语、头像和通知入口；中部展示步数、睡眠、心率三张数据卡片；下方提供今日训练、饮水提醒和健康建议。整体使用低饱和绿色与米白色，简洁、轻盈、专业，圆角卡片、清晰信息层级、充足留白。使用简短中文文案，避免乱码、过度渐变、过多装饰和无法理解的图标。
任务 / 用户 / 目标页面结构视觉风格限制条件

比例参数

  • 手机界面：9:16 或明确设备画布。
  • 网页方案：16:9 或 1440px 桌面画布。
  • 海报、Banner、电商主图要写具体用途与尺寸。

风格参数

  • 不要只写“高级”，要拆成色彩、材质和排版。
  • 例如：低饱和、无衬线、轻阴影、圆角 16px、Bento 布局。
  • 风格词之间要相互兼容，避免矛盾堆叠。

约束参数

  • 避免乱码、错误图标、无意义数据和过密布局。
  • 保留指定结构，不改变关键模块位置。
  • 不要复制参考图的品牌标识和独特构图。
模糊 Prompt“生成一个高级、好看的健康 App 页面。”模型不知道用户、任务、结构、比例和评价标准。
VS
结构化 Prompt明确页面目标、模块顺序、真实内容、视觉语言、输出比例和禁止项。

Prompt 不是关键词堆砌

“极简、赛博、复古、柔和、奢华、卡通”同时出现会产生冲突。风格词要围绕同一设计目标，并转化为具体视觉规则。

Prompt 改写练习

把“做一个高级的咖啡 App”改写为包含任务、用户、结构、风格、比例和约束的完整 Prompt。

06 / EVALUATION & ITERATION

生成之后如何判断：不只选“最好看”，而是选最符合目标、最值得继续的方向。

评价标准越具体，修改指令越有效。先检查目标和结构，再看视觉细节；先解决大问题，再修小问题。

07 / PRACTICE TASK

实践任务：围绕同一页面主题，生成、比较并优化 3 个 UI 方向。

练习重点不是一次生成完美，而是训练需求拆解、Prompt 表达、变量控制、方案比较和修改反馈。

实践路径

定义 → 生成 → 比较 → 优化
01 选择主题确定产品类型、目标页面、目标用户和核心任务。
02 拆解结构列出页面模块、内容优先级、关键操作和必要状态。
03 编写 Prompt补充视觉风格、画布比例、真实内容、参考与限制条件。
04 生成三版保持页面目标一致，每版只改变一个主要视觉方向。
05 评价优化按统一标准筛选一版，并完成一轮定向修改。
01

选择主题

从健康、教育、电商、效率工具或旅行中选择一个产品页面，说明谁在什么场景下使用。

02

建立 Brief

写出核心任务、必备模块、真实内容、画布比例和视觉关键词。

03

生成 3 个方向

保持页面目标和结构一致，只改变极简、科技、Bento、柔和生活方式等视觉语言。

04

点评并优化

根据目标、布局、可读、一致和落地性选择一版，并用定向指令完成一轮修改。

实践产出清单

  • 基础 Brief：产品、用户、页面目标和必备模块。
  • 基础 Prompt：完整 8 段信息，不只是风格关键词。
  • 三张概念图：三个方向有清晰、可说明的差异。
  • 变量记录：说明每一版改变了哪些条件。
  • 评价表：按照六个维度打分并写出取舍。
  • 优化版本：保留有效部分，完成一次定向修改。

先说明目标和选择依据，再记录反馈，最后从目标、结构、视觉和落地四个层面复盘，不只评价“好不好看”。

继续完善

把选中的概念图带入 Figma，重建一个完整页面，并补充组件状态、真实文案、网格和设计规范。

核心结论：AI 负责扩展视觉可能性，设计师负责定义问题、控制方向并完成真实落地。

先认识模型边界，再选择合适输入；用结构化 Prompt 控制任务，用统一评价标准筛选结果，最后把概念图重建为真实、可用、可交付的设计。
