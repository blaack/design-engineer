01 / GPT IN UI DESIGN

GPT 在 UI 设计中的定位：辅助思考、整理信息、加速表达。

GPT 可以帮助你把零散想法变成结构化内容，但它不会自动理解真实业务、品牌调性和用户场景。设计判断仍然需要由人来完成。

GPT = 逻辑中枢 + 文案助手 + Prompt 教练

在 UI 设计流程中，它适合做需求梳理、页面结构、内容生成、设计说明和方案对比。它能提高表达效率，但不能代替设计师对用户、业务和视觉质量的判断。

梳理把需求拆成模块、层级和页面结构。
生成输出 IA、竞品分析、微文案、说明文。
对比给出方案差异、优缺点和修改方向。
追问提示缺失信息，帮助补全需求边界。
复盘总结可复用模板和下一轮优化点。
审稿检查逻辑、格式、遗漏和表达清晰度。

辅助而非替代
信息架构 IA整理页面导航、模块顺序、内容分组和层级关系。
竞品分析按功能、视觉、内容、用户路径拆解竞品差异。

使用原则：把 GPT 当作共创工具。先让它帮你生成方向，再用设计判断筛选、修改和落地。
02 / PROMPT STRUCTURE

高质量 Prompt 的基础结构：先讲清楚，再要求输出。

不要只写“帮我做一个好看的首页”。清楚的 Prompt 要像一份小型设计需求，包含角色、背景、任务、约束、输出格式和参考标准。

01

角色 Role

让 AI 知道以什么身份回答。例如：资深 UI 设计师、产品经理、UX 文案设计师、竞品分析师。

02

背景 Context

说明产品、用户、业务场景和页面目标。例如：AI 学习 App，面向大学生，首页要帮助用户开始今日学习。

03

任务 Task

明确需要生成什么内容。例如：设计首页信息架构、输出模块清单、写 3 组 Banner 文案。

04

约束 Constraint

控制风格、范围、尺寸、组件、语气和不要出现的内容。例如：简洁科技感，不要杂乱背景。

05

输出 Output

规定输出格式。例如：用 Markdown 表格输出，包含模块名称、内容、交互、视觉重点。

06

标准 Standard

说明判断标准和参考方向。例如：信息清晰、组件可落地、视觉层级明确、适合移动端。

03 / UI PROMPT DIMENSIONS

UI 设计 Prompt 必须说清：页面、场景、层级、风格、组件、输出。

UI Prompt 的重点不是“好看”，而是让 AI 明白页面类型、用户正在做什么、哪些信息最重要、界面由哪些组件组成，以及最终要以什么形式交付。

页面类型

  • 首页、详情页、搜索页、登录页、数据看板、支付页。
  • 不同页面的目标不同，信息组织方式也不同。

用户场景

  • 用户是谁？在什么情况下使用？想完成什么任务？
  • 场景越清楚，输出越接近真实产品需求。

信息层级

  • 主标题、核心入口、内容模块、辅助说明如何排序？
  • 让 AI 先帮你拆结构，再考虑视觉细节。

视觉风格

  • 说明关键词：简洁、科技、年轻、轻量、专业、温暖。
  • 同时说明不要什么：不要厚重阴影，不要杂乱背景。

组件要求

  • 导航、Banner、卡片、按钮、标签、表单、列表、弹窗。
  • 必要时补充默认、点击、加载、错误、空状态。

输出形式

  • 页面结构、组件清单、表格、文案方案、Prompt 模板。
  • 输出格式明确，后续修改和复用更方便。

正向要求 + 负向限制

控制输出边界
正向要求简洁科技感、信息清晰、卡片式布局、主 CTA 明确、移动端优先。
+
负向限制不要杂乱背景、不要过多装饰、不要伪英文、不要只输出抽象形容词。
04 / BETTER QUESTIONING

高质量提问方式：用结构化表达减少误解。

提问质量会直接影响输出质量。把需求拆成段落、列表或表格，可以让 GPT 更稳定地理解目标，也更容易得到可执行的回答。

用 Markdown 组织需求

  • 用标题分区：背景 / 任务 / 约束 / 输出。
  • 用列表列出页面模块、组件和风格关键词。
  • 避免把所有要求塞进一句长句。

明确输出格式

  • 可以要求输出表格、页面结构、组件清单、文案方案。
  • 也可以要求输出“可直接给设计师使用的 Prompt”。
  • 格式越具体，后续修改成本越低。

通过追问优化

  • 第一轮先得到结构，第二轮补细节。
  • 发现不准确时，指出问题并让它重写。
  • 最后总结成可复用模板。

05 / REUSABLE PROMPT TEMPLATE

可复用 Prompt 模板：把需求写成可替换的结构。

通用 UI Prompt 模板

适合首页、详情页、搜索页、活动页、数据看板等 UI 需求。

06 / GPT OUTPUT FORMATS

GPT 可输出格式：先决定交付形态，再让内容进入正确容器。

GPT 不只能输出一段文字。你可以要求它用表格、JSON、YAML、HTML、组件清单、设计说明、Prompt 模板等格式交付，让结果更容易复制、修改、导入工具或交给团队协作。

结构化阅读格式

  • Markdown 表格：适合页面模块、竞品分析、组件清单。
  • 编号列表：适合流程步骤、设计原则、修改建议。
  • 分层大纲：适合信息架构、课程目录、页面内容层级。

可机器读取格式

  • JSON：适合配置、组件属性、数据结构、接口示例。
  • YAML：适合轻量配置、字段说明、模板化内容。
  • CSV：适合批量文案、标签、表单字段和测试用例。

可直接交付格式

  • HTML / CSS：适合快速生成页面原型和组件示例。
  • PRD / 设计说明：适合交给产品、设计和开发同步。
  • Prompt 模板：适合复用到下一次相似任务。

07 / REVERSE FROM FORMAT

从格式反推提示内容：看到想要的结果，就能倒推出该怎么问。

当你不知道 Prompt 怎么写时，可以先定义“最后想拿到什么格式”。输出字段就是提问线索：每一个表格列名、JSON 字段或设计说明段落，都在提醒你需要补充哪些背景、约束和判断标准。

反推方法：先看输出字段

第 1 步：确定最终格式例如：Markdown 表格、JSON、HTML 页面、设计 Brief、组件清单。
第 2 步：列出字段例如：模块名称、用户目的、组件需求、交互状态、视觉重点、优先级。
第 3 步：把字段变成问题每个字段都对应一个需要告诉 GPT 的信息或让 GPT 推导的任务。
第 4 步：补充边界说明产品、用户、页面目标、风格、设备、不要出现的内容。
第 5 步：写成完整 Prompt把角色、背景、任务、约束、输出格式组合成一段可执行指令。
