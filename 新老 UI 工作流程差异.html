01 / WORKFLOW OVERVIEW

从 PRD 到设计交付的完整链路，正在被 AI 重新分配时间。

传统流程更像线性推进，AI 工作流更像并发探索。AI 不是跳过设计过程，而是把部分低价值重复劳动压缩，让设计师把注意力放在更重要的判断上。

02 / TRADITIONAL UI PROCESS

梳理传统 UI 项目流程：设计不是直接画图。

传统流程的价值不只是产出画面，而是通过阅读需求、理解行业、拆解信息、制定视觉标准，最终完成可交付、可开发、可走查的设计方案。

PRD 如何阅读

  • 先看项目目标和业务指标
  • 提取用户角色、场景和核心路径
  • 整理页面清单、功能模块和状态
  • 标记不明确、冲突和需要确认的问题

设计不是直接画图

  • 理解需求和业务目标
  • 理解行业规则
  • 理解行业视觉标准
  • 补充 UI 设计相关知识储备

传统设计产出

  • 低保真原型
  • Moodboard 风格探索
  • 高保真视觉设计
  • 标注交付与开发资源

走查的顺序

  • 先看页面结构和主流程
  • 再看视觉还原、字号、间距、颜色
  • 检查组件状态、边界状态、异常状态
  • 最后检查交互、适配和开发实现

传统流程中最耗时的环节

  • 反复沟通：需求不清、边界不清、优先级不清
  • 重复绘制：同类页面、同类组件、同类状态反复画
  • 手动适配：多尺寸、多端、多状态逐一调整
  • 反复走查：视觉还原、交互细节和开发偏差需要多轮修正

04 / THINKING DIFFERENCE

对比“手工绘制”与“AI 协作”的思考差异。

AI 改变的不只是工具，而是设计师思考问题的方式：从“怎么画”变成“要什么结果”，从“单稿打磨”变成“多方案筛选”。

手工流程关注“怎么画”设计师需要花大量时间思考图形、排版、对齐、素材和细节如何手动完成。
VS
AI 流程关注“要什么结果”设计师更需要描述目标、风格、模块、约束和判断标准，让 AI 朝正确方向生成。
传统修改常常推倒重来当方向不对时，可能需要重新找参考、重画结构、重做视觉稿。
VS
AI 修改更多依赖指令微调通过补充限制、强调问题、指定局部区域，让结果逐步接近目标。
固定组件库传统项目更依赖已有组件和固定资产，扩展成本相对较高。
VS
可扩展的动态素材库AI 可以根据风格快速生成图标、插画、背景、文案和变体素材。
人与人协作主要围绕产品、设计、开发之间的沟通和交付进行。
VS
人与模型、工具链协作设计师需要组织 GPT、Figma、图像生成工具、代码工具和开发流程一起工作。
05 / IMAGE GENERATION

图片生成：把视觉想法快速变成可讨论的方案。

图片生成适合用于前期发散、素材补充、视觉方向测试和营销内容产出。它不是直接替代最终设计稿，而是帮助设计师更快看到不同风格、构图和画面可能性。

06 / IMAGE PROCESSING

图像处理：把已有素材修好、补齐、统一并适配。

图像处理更适合处理“已有图片”的问题，例如清晰度不足、背景不统一、尺寸不匹配、局部内容需要替换、产品图需要统一风格等。它让素材从“能看”变成“能用”。

抠图、换背景、扩图、局部重绘、商品图统一、图片修复、风格统一、多尺寸适配。
适合把素材从“能看”处理到“能用”。重要图片要人工检查边缘、文字、手部、商品结构和品牌一致性。

基础修图

  • 处理亮度、对比度、色温、噪点和清晰度问题。
  • 修复轻微瑕疵、压缩损失、模糊边缘和脏点。
  • 让素材在页面中保持干净、清楚、可识别。

抠图与换背景

  • 移除复杂背景，保留人物、商品、图标或主体物。
  • 替换成品牌色背景、渐变背景、场景背景或透明底。
  • 适合商品图、头像图、运营图和活动素材。

扩图与补图

  • 把横图扩成竖图，把方图扩成 Banner 或海报比例。
  • 补齐画面边缘、背景空间、视觉留白和构图缺失。
  • 常用于多尺寸广告、社媒封面和网页头图适配。

局部替换

  • 替换局部元素，例如按钮、图案、道具、背景物和小装饰。
  • 保留原图主体和整体光影，只改变需要调整的部分。
  • 适合快速修正视觉问题和增加营销氛围。

风格统一

  • 把多张不同来源的图片统一成同一调性。
  • 统一色彩、材质、光影、插画风格和视觉颗粒度。
  • 适合组件库、图标库、活动素材包和品牌视觉资产。

批量适配

  • 把同一张图适配为移动端、网页端、社媒端和投放尺寸。
  • 自动调整主体位置、留白比例和关键内容区域。
  • 减少重复切图和多尺寸手动排版时间。

文字与画面融合

  • 根据画面预留标题、副标题、价格、按钮和规则区域。
  • 控制文字可读性、背景对比度和视觉层级。
  • 适合海报、Banner、活动页和电商主视觉。

质量检查

  • 检查是否出现变形、错字、脏边、异常手部和逻辑错误。
  • 检查图片是否符合品牌规范、投放规范和页面尺寸。
  • 重要素材必须经过人工复核后再上线。

07 / VECTOR GENERATION

矢量生成：把图形变成可编辑、可缩放、可复用的设计资产。

矢量生成的价值在于可编辑和可复用。它可以把图标、线稿、装饰图形、信息图、简单插画转成 SVG 或路径资源，用于网页、组件库、印刷和设计源文件。

输出后要检查路径数量、节点复杂度、颜色可编辑性和小尺寸可读性；上线前建议压缩 SVG。

图标矢量化

  • 把图片图标、手绘草图或 AI 生成图标转成 SVG。
  • 统一线宽、圆角、端点、填充方式和视觉重量。
  • 适合进入 App、网页、后台系统和组件库。

Logo 与标识

  • 将初步 Logo 方案整理成清晰的矢量路径。
  • 输出横版、竖版、图形标、单色版和反白版。
  • 方便后续做品牌规范、印刷文件和网页应用。

插画与装饰图形

  • 生成线性插画、扁平插画、几何装饰和背景纹理。
  • 控制色块数量、层级结构和可编辑程度。
  • 适合页面空状态、引导页、运营活动和说明图。

信息图与流程图

  • 把复杂内容整理成流程图、结构图、数据图和说明图。
  • 用矢量方式保证文字、线条和节点清晰可缩放。
  • 适合课程课件、方案汇报、产品说明和官网图示。

SVG 代码资源

  • SVG 既是图像，也是可以编辑、压缩和复用的代码。
  • 可直接嵌入网页、组件、图标库或动效系统。
  • 适合做 hover、描边动画、路径动画和响应式图形。

矢量检查要点

  • 检查路径是否过多、节点是否复杂、颜色是否可控。
  • 检查放大后是否清晰，小尺寸下是否仍然可识别。
  • 上线前需要压缩 SVG，并移除无用图层和冗余代码。

课程页面用于知识讲解、模块拆分、案例展示和学习路径整理。
作品集页面用于设计师个人主页、项目展示、案例详情和视觉包装。
App 页面 Demo用于移动端界面结构预览、状态展示和交互说明。
后台页面 Demo用于表格、筛选、图表、数据卡片和管理流程验证。
动效页面用于滚动动画、SVG 动画、粒子背景、视差和交互效果测试。

生成 HTML 时要说明什么

页面目标说明页面用于展示、转化、教学、活动、工具还是产品介绍。
内容结构列出 Hero、导航、核心卖点、案例、流程、表格、FAQ、CTA 等模块。
视觉风格说明配色、字体气质、卡片样式、图形语言、空间感和参考方向。
交互动效说明滚动揭示、悬停反馈、按钮形变、SVG 动画、背景粒子等效果。
适配要求说明宽屏、平板、移动端、打印、深色模式或全屏布局要求。
交付格式说明要单文件 HTML、拆分 CSS/JS、可下载资源或可继续开发的结构。

HTML Demo 生成流程

需求 → 结构 → 样式 → 交互 → 验证
整理需求明确页面目的、目标用户、内容模块和核心信息。
搭建结构先写语义化 HTML，确认模块顺序和信息层级。
设计样式用 CSS 完成布局、颜色、字体、卡片、间距和响应式。
加入动效根据需要加入滚动、悬停、过渡、SVG 或轻量 JS 交互。
检查适配检查宽屏、移动端、内容溢出、中文换行和浏览器兼容。
继续迭代根据反馈调整模块、文案、视觉密度、动效强度和代码结构。
09 / RESOURCE APPLICATION

资源应用：把 AI 生成结果转成真正能交付、能开发、能复用的文件。

AI 生成只是第一步，真正的工作流还包括整理、转换、命名、压缩、标注和交付。资源应用的目标是让生成内容进入设计源文件、开发环境、运营流程和知识库。
