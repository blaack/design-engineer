01 / UI DESIGN CONCEPT

UI 设计概念：连接用户、产品功能与视觉表达。

UI 是 User Interface 的缩写，即用户界面。它不是单纯的视觉装饰，而是把产品内容、功能路径、操作反馈和品牌感组织成用户可以理解、可以操作的界面。

UI = 信息 + 操作 + 反馈 + 品牌感

一个可用界面要先让用户知道“这是什么、我能做什么、下一步在哪里、操作后发生了什么”。视觉风格可以吸引注意力，但清晰的信息结构和稳定的交互反馈才是 UI 的基础。

信息标题、正文、图片、价格、说明、规则。
操作按钮、入口、导航、表单、搜索、筛选。
反馈点击、加载、成功、错误、空状态、禁用。
品牌颜色、字体、图形、语气、插画和氛围。

从图片到界面的判断

可用性优先
看懂内容用户能否快速理解页面主题、核心信息和当前状态。
找到操作入口、按钮和下一步动作是否明确，不需要猜测。
获得反馈操作前后是否有清楚的状态变化和结果说明。
形成系统同类组件、间距、圆角、颜色和文字规则是否统一。
能够落地布局、素材、组件和状态是否能被拆分、标注和开发。

UI 不是单张海报

  • 海报强调视觉吸引，UI 更强调任务完成。
  • UI 需要按钮、状态、反馈、路径和规则。
  • 越复杂的产品，越需要稳定的界面系统。

UI 不是功能堆叠

  • 功能很多不等于体验好。
  • 信息需要分组、排序、隐藏和突出。
  • 界面要帮助用户少思考、少犯错、快完成。

UI 不是只靠审美

  • 审美解决吸引力，结构解决理解效率。
  • 规范解决一致性，交互解决使用路径。
  • 落地性决定设计能否进入真实产品。

BASICS / BASIC DIMENSIONS

UI 基础维度：把抽象审美变成可检查的规则。

一张界面可以从信息层级、布局间距、颜色对比、字体文案、组件状态五个基础维度进行拆解。

信息层级

  • 用户第一眼看到什么？
  • 主标题、副标题、正文、按钮是否有顺序？
  • 重要信息是否被弱化或隐藏？

布局与间距

  • 模块之间是否有清楚分组？
  • 对齐是否统一？
  • 卡片内外间距是否稳定？

颜色与对比

  • 主色、辅助色、警示色是否清楚？
  • 文字和背景对比是否足够？
  • 颜色是否服务信息，而不是只制造氛围？

字体与文案

  • 字号层级是否清楚？
  • 字重和行距是否一致？
  • 文案是否真实、无错字、可理解？

组件与状态

  • 按钮、输入框、标签、卡片是否统一？
  • 是否有默认、点击、禁用、错误、加载状态？
  • 组件是否能复用和开发实现？

App 截图观察示例

今日精选课程 主标题清楚，副标题辅助说明，行动按钮需要更突出。

界面观察路径

第一步：先看任务这个页面让用户完成什么？是浏览、购买、登录、填写资料，还是提交订单？
第二步：再看重点用户第一眼能不能看到最重要的信息？页面有没有清晰主次？
第三步：看操作路径按钮在哪里？下一步是什么？用户是否需要猜测？
第四步：看状态完整度空状态、错误状态、加载状态、禁用状态是否考虑到？
第五步：看落地性组件是否统一，尺寸是否稳定，开发是否可以复用和实现？
判断原则：不要只问“好不好看”，要追问“哪里影响理解、哪里影响操作、哪里影响落地”。
04 / AI UI REVIEW

AI 生成图为什么不能直接用：它常常像 UI，但不一定是产品界面。

AI 图适合做灵感、风格探索和快速预览，但不能直接当成可交付 UI。判断一张 AI UI 图时，要从信息、层级、组件、交互和落地五个维度逐项审稿。

信息清晰

标题、说明、入口、价格、状态是否真实清楚。

  • 是否出现无意义文案？
  • 是否有错字、乱码、伪英文？
  • 用户是否知道页面目标？

视觉层级

视觉重点是否对应业务重点，而不是所有元素都很抢。

  • 主 CTA 是否突出？
  • 重要内容是否被装饰压住？
  • 字号、字重、颜色是否有层级？

组件规范

按钮、卡片、输入框、标签是否统一，是否像一个系统。

  • 同类按钮样式是否一致？
  • 圆角、阴影、间距是否统一？
  • 是否可以沉淀为组件？

交互完整

页面不是静态海报，需要考虑用户操作前后发生什么。

  • 点击后去哪里？
  • 加载、错误、成功状态在哪里？
  • 异常路径是否被处理？

可落地性

设计是否能被开发实现、适配、维护和复用。

  • 布局是否适合真实屏幕？
  • 素材和图层是否可拆分？
  • 是否有响应式或边界考虑？
01 / 信息清晰

先判断页面是否能被读懂

AI 经常生成“看起来像文字”的内容，但真实 UI 需要让用户快速理解页面目标、核心信息和下一步动作。

  • 关键判断：标题、价格、状态、说明、按钮文案必须真实可读，不能只有装饰感。
  • 检查方法：遮住装饰元素，只看文字和入口，判断用户是否还能理解页面要做什么。
  • 修改方向：重写核心文案，减少无意义英文和假数据，突出页面主目标。
02 / 视觉层级

看重点是否真的对应业务重点

很多 AI 图会把背景、图片、标签、按钮都做得很抢，导致用户不知道先看哪里、先点哪里。

  • 关键判断：视觉焦点应该服务页面任务，主标题、主 CTA 和关键利益点要有明显优先级。
  • 检查方法：眯眼看页面，判断第一眼看到的是核心内容，还是装饰和无关元素。
  • 修改方向：调整字号、字重、颜色对比和留白，让主次关系更清楚。
03 / 组件规范

判断它是不是一个统一的系统

真实产品界面需要复用组件。AI 图常见问题是按钮、卡片、标签和输入框各画各的，看起来丰富但无法形成规范。

  • 关键判断：同类组件要保持一致的尺寸、圆角、阴影、间距、图标位置和文字规则。
  • 检查方法：把所有按钮、卡片、标签单独圈出来，观察它们是否来自同一套组件规则。
  • 修改方向：统一按钮等级、卡片结构和标签样式，沉淀成可复用组件。
04 / 交互完整

静态好看不代表可以操作

UI 不是海报。用户点击、输入、等待、失败、成功时，界面都需要提供明确反馈。

  • 关键判断：除了默认状态，还要考虑加载、禁用、错误、成功、空状态和边界情况。
  • 检查方法：沿着主要操作路径问三件事：点哪里、去哪里、出错怎么办。
  • 修改方向：补齐关键状态和反馈文案，让页面从“静态图”变成“可操作界面”。
05 / 可落地性

最后判断它能不能被实现和维护

AI 图可能有复杂光效、混乱图层和不稳定结构。可交付 UI 需要能拆分、适配、标注和开发实现。

  • 关键判断：布局要适合真实屏幕尺寸，图层和素材要能拆，模块要能响应不同内容长度。
  • 检查方法：把页面拆成模块，判断每个模块是否有固定规则、边界情况和复用价值。
  • 修改方向：简化装饰，稳定网格和间距，补充组件尺寸、状态和响应式规则。

核心结论

AI 可以快速生成视觉参考，但真正的 UI 设计必须经过审稿、重构和落地验证。

适用场景

这套检查清单适合用于 AI 图筛选、界面修改、作品点评和设计方案复盘。

评价重点

用专业语言说清楚问题：从“感觉不对”转化为信息、层级、组件、状态、反馈和落地问题。

UI 基础理论的价值，是让你能判断 AI 结果，而不是被 AI 结果牵着走。

看起来像 UI 的图片，不一定能成为产品界面。信息、层级、组件、状态、反馈和可落地性，才是判断一张 UI 图是否可用的核心标准。
